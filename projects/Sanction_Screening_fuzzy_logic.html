Can a name still be recognized
when it's written wrong?

Building a sanctions screening pipeline that goes beyond exact matching—combining blocking, fuzzy string similarity and phonetic matching to identify potentially sanctioned entities hidden behind typos, reordered names and transliterations.

01 · Situation

The problem: names are messy.

A sanctions screening system cannot rely on an exact name match. A legitimate payment message might contain "Mohammed Al Rashid", while the sanctions list contains "Muhammad Rashid".

Add a typo, a missing middle name, reordered tokens or a transliteration—and a simple lookup can miss the entity entirely. At the same time, overly aggressive matching can overwhelm analysts with false alerts.

The goal was therefore not simply to ask "Does this name match?" but rather: "How strong is the evidence that these two names represent the same entity?"

02 · Task

Turn fuzzy names into measurable risk signals.

I designed a screening pipeline that converts noisy transaction names into a composite similarity score, then evaluates how well that score separates true sanctions hits from clean transactions.

The data

The reference data came from OpenSanctions, using entity, name and sanctions information. The transaction dataset was synthetically generated to create a controlled evaluation environment.

Creating realistic noise

Instead of testing only perfect matches, I injected realistic perturbations into sanctioned names:

  • Character-level typos
  • First/last name reordering
  • Missing name tokens
  • Common transliteration variations
  • Titles and honorifics

03 · Action

From millions of comparisons to one explainable score.

The screening architecture was designed in layers—first reducing the search space, then measuring similarity, and finally evaluating the operational trade-off between catching hits and generating alerts.

1
Normalize

Lowercase names, remove punctuation and honorifics, and standardize whitespace.

2
Block

Use Soundex on the first token to reduce the number of candidate comparisons.

3
Score

Combine five complementary similarity measures into one composite score.

4
Evaluate

Test thresholds using precision, recall, F1, AUC, KS and operational alert metrics.

The composite score

Rather than trusting a single fuzzy-matching algorithm, the model combines:

  • Levenshtein ratio — character-level similarity
  • Token-set ratio — robustness to token differences
  • Token-sort ratio — robustness to reordered names
  • Jaro-Winkler — useful for short names and prefixes
  • Phonetic matching — captures sound-based similarity

The final score weighted these signals at 25%, 25%, 20%, 20% and 10%, respectively.

The key lesson wasn't simply that fuzzy matching worked. It was that model performance and operational performance are different questions. A lower threshold can maximize detection but generate an impractical number of alerts. Threshold selection therefore needs to balance missed sanctions risk against analyst workload.

What the feature analysis revealed

When evaluated individually, token-sort similarity was the strongest single discriminator with an AUC of 0.9808. Levenshtein also performed strongly at 0.9787, while Jaro-Winkler achieved 0.9380.

Interestingly, the phonetic feature alone had an AUC of 0.50, illustrating why combining multiple signals can be more useful than relying on a single matching technique.

The takeaway

Good screening isn't just about finding matches.

This project demonstrates how I approach a real-world model problem: start with messy data, engineer meaningful signals, design an efficient scoring pipeline, and then evaluate the model from both a statistical and business perspective.

The next step for a production-grade system would be to incorporate additional entity attributes—such as date of birth, nationality, address and identifiers—and calibrate thresholds against real investigator outcomes.

Data science lesson: The hardest part of entity resolution is rarely calculating similarity. It is deciding which similarities matter, how much evidence is enough, and what the cost of being wrong looks like.
